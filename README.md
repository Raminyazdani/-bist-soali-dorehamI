# روی پیشونی!

یک بازی فارسی بیست‌سؤالی برای دورهمی: هرکس با گوشی خودش، ورود با کد لابی، کارت متنی یا عکس‌دار و جدول امتیاز. بدون حساب، نصب یا لپ‌تاپ میزبان.

[آدرس بازی](https://rooye-pishooni.vercel.app/) · [گزارش مشکل](https://github.com/Raminyazdani/-bist-soali-dorehamI/issues) · [تغییرات نسخهٔ عمومی](https://github.com/Raminyazdani/-bist-soali-dorehamI/pull/1)

**وضعیت انتشار — ۲۰۲۶-۱۰-۱۲:** طبق درخواست تازه، همین پروژه با بک‌اند رایگان Neon ادامه پیدا می‌کند. دیتابیس واقعی آماده است و ۴۳ آزمون زندهٔ ذخیره‌سازی موفق بوده‌اند؛ آزمون‌های کامل native، Preview و Production نسخهٔ تازه هنوز در انتظارند. آدرس اصلی فعلاً نسخهٔ قبلی با Blob معلق را اجرا می‌کند و قابل استفاده نیست. هیچ پرداخت یا ارتقای پولی انجام نشده است. وضعیت دقیق در [STATUS.md](STATUS.md) و [VERIFICATION.md](VERIFICATION.md) است.

## بازی چطور کار می‌کند؟

۱. ۲ تا ۱۲ نفر جمع شوید. یک نفر لابی می‌سازد، تعداد کارت هر نفر را بین ۱ تا ۲۰ تعیین می‌کند و کد شش‌رقمی یا لینک را به بقیه می‌دهد. با آمادگی همه، مدیر کارت‌سازی را شروع می‌کند.

۲. هر نفر کارت‌های خودش را می‌نویسد. متن لازم است؛ عکس اختیاری و قابل تعویض یا حذف است. متن‌ها خودکار ذخیره می‌شوند. با آمادگی همه، کارت‌ها و ترتیب بازیکن‌ها تقسیم می‌شوند.

۳. کارت خودت به تو نمی‌رسد و هر کارت دقیقاً یک بار بازی می‌شود. کارت‌های نویسنده‌های دیگر در هر دست تا حد ممکن برابرند؛ مثلاً در جمع چهارنفره با سه کارت، از هر دوست یک کارت می‌گیری. در جمع دونفره طبیعتاً همهٔ کارت‌ها از نفر دیگرند.

۴. وقتی نوبتت شد، گوشی را بالای سرت و رو به بقیه بگیر. داور شروع را می‌زند؛ بعد از شمارش معکوس سه‌ثانیه‌ای، کارت ظاهر می‌شود و زمان می‌رود. داور هر سؤال یا حدس مستقیم را یک بار ثبت می‌کند. سؤال اشتباه قابل برگشت است. برای جلوگیری از لمس اشتباهی، ثبت برد یا باخت پنجرهٔ تأیید دارد.

۵. حدس درست به تعداد سؤال‌های باقی‌مانده امتیاز می‌دهد؛ شکست صفر. بعد از سؤال بیستم هنوز جواب آخر قابل ثبت است. پایان ناموفق را داور ثبت می‌کند. مکث و شمارش معکوس در زمان نوبت حساب نمی‌شوند.

۶. جدول پایانی بر اساس مجموع امتیاز بیشتر مرتب می‌شود؛ در تساوی، مجموع زمان **همهٔ نوبت‌های پایان‌یافته، برد و باخت** کمتر بهتر است. تساوی دقیق رتبهٔ مشترک دارد. کارت‌ها، نویسنده‌ها و نتیجهٔ هر نوبت هم نمایش داده می‌شوند. بازی تازه کارت‌ها و امتیازها را پاک می‌کند و همان جمع می‌ماند.

## لابی و اتصال

- گوشی سازنده میزبان نیست. بیرون رفتنش برای پیدا کردن عکس، کارت‌سازی یا بازی دیگران را متوقف نمی‌کند. اینترنت لازم است؛ وضعیت گوشی‌ها حدود هر ۱٫۶ ثانیه هماهنگ می‌شود و تایمر روی گوشی روان حرکت می‌کند.
- اگر بازیکن نوبت یا داور بیش از ۲۰ ثانیه قطع شود، زمان خودکار مکث می‌شود. داور پس از برگشت اتصال ادامه را می‌زند.
- مدیر می‌تواند داور را عوض کند یا مدیریت را به دیگری بدهد. بعد از ۴۵ ثانیه نبودن مدیر، دیگری می‌تواند مدیریت را بگیرد.
- خروج معمولی از لابی فقط خودت را خارج می‌کند؛ مدیریت به بازیکن باقی‌مانده می‌رسد. در وسط بازی، برای حفظ نوبت‌ها، خروج از صفحه به معنی حذف بازیکن نیست؛ با همان مرورگر برگرد.
- حذف بازیکن، بستن لابی و پاک‌کردن بازی تأیید می‌خواهند. حذف در وسط بازی، با تأیید، بازی فعلی را پاک می‌کند و باقی جمع را به لابی برمی‌گرداند. سازنده یا مدیر می‌تواند لابی را برای همه ببندد.
- لابی ۲۴ ساعت از زمان ساخت معتبر است. هرکس کد را داشته باشد، تا پیش از شروع می‌تواند وارد شود؛ کد را به جمع خودتان بدهید.

## اطلاعات بازی

اسم، متن و عکس کارت‌ها برای همان لابی ذخیره می‌شوند. کارت‌های آینده به سایر بازیکن‌ها ارسال نمی‌شوند. عکس‌ها در ذخیره‌سازی خصوصی‌اند؛ لینک موقت عکس، کلید ورود به لابی را ندارد و سرور هنگام نمایش عضویت و دسترسی به آن کارت را بررسی می‌کند. داده‌های منقضی با وظیفهٔ روزانه پاک می‌شوند. کلید برگشت به لابی فقط در همین مرورگر ذخیره می‌شود. حساب کاربری و ابزار تحلیل بازدید اضافه نشده است.

## اجرای محلی

Node.js 24 و npm:

```sh
npm ci
npm run build
npm run dev
```

سپس `http://localhost:5173` را باز کنید. اجرای محلی به حساب یا کلید ورسل نیاز ندارد و از یک آداپتر ذخیره‌سازی روی دیسک استفاده می‌کند. این آداپتر در استقرار ورسل استفاده نمی‌شود.

```sh
npm test
node test/browser-e2e.mjs
node test/photo-e2e.mjs
node test/lobby-e2e.mjs
node test/background-e2e.mjs
```

برای تست‌های مرورگر، Chromium باید نصب باشد (`npx playwright install chromium`). برای اجرای همان تست روی یک استقرار واقعی، `E2E_URL` را به آدرس آن بدهید. تست‌ها لابی‌های آزمایشی می‌سازند. شواهد محلی در `test-output/` قرار می‌گیرند و وارد گیت نمی‌شوند. CI، تست‌های منطق/HTTP و build را روی هر PR اجرا می‌کند.

## استقرار روی ورسل

همین ریپو و پروژهٔ موجود را با Vite، build برابر `npm run build` و خروجی `dist` حفظ کنید. Vercel Functions و **Neon Free Postgres** بک‌اند هستند: وضعیت لابی، حضور، محدودیت درخواست و عکس‌های خصوصی در SQL ذخیره می‌شوند. هر درخواست آداپتر تازه دارد؛ نسخهٔ بدنه و نوشتن شرطی CAS مانع از گم‌شدن تغییرات هم‌زمان می‌شوند. حافظهٔ تابع یا گوشی منبع اصلی وضعیت نیست. Blob برای این نسخه لازم نیست.

۱. دیتابیس رایگان موجود در `fra1` به Preview و Production همین پروژه وصل شده است. کلید دیتابیس فقط `DATABASE_URL` سرور است؛ هرگز نام `VITE_` نداشته باشد یا وارد گیت/مرورگر شود. برای آماده‌کردن جدول‌ها، فایل env واقعی و نادیده‌گرفته‌شده را صریح بدهید؛ اسکریپت جدول‌ها را بدون حذف داده می‌سازد:

```sh
node scripts/init-postgres.mjs .env.neon.preview.local
```

۲. `CRON_SECRET` تصادفی و سروری Production، API پاک‌سازی را محافظت می‌کند. `vercel.json` پاک‌سازی روزانه را ساعت ۰۴:۰۰ UTC فراخوانی می‌کند؛ کران فقط در Production فعال است. اعتبار لابی ۲۴ ساعت است و عکس‌ها با پایان/پاک‌شدن داده‌های مرتبط حذف می‌شوند.

۳. Preview واقعی را با ساخت/ورود، متن و عکس، آمادگی، نتیجه و جدول، برگشت بازیکن، تأییدهای حساس و نبودن گوشی سازنده تست کنید. همان HEAD آزموده‌شده را به `master` مرج کنید؛ انتشار از اتصال Git ورسل انجام می‌شود. سپس آدرس اصلی و پاک‌سازیِ دارای مجوز را مستقلاً بررسی کنید. READY و build به‌تنهایی بازی آنلاین را تأیید نمی‌کنند.

محدودیت ساخت/ورود/آپلود و ثبت تکراری درخواست حفظ شده است. پاسخِ وضعیتِ بدون تغییر سبک‌تر است؛ تغییر بازی و تمدید لینک عکس همچنان وضعیت کامل را می‌خوانند. سهمیهٔ رایگان محدود است: ۱ گیگابایت ذخیره‌سازی، ۱۰۰ CU-hour محاسبه و ۵ گیگابایت خروجی داده؛ ظرفیت نامحدود وعده داده نمی‌شود. هیچ پرداخت، trial یا ارتقای Vercel انجام نشده است.

دادهٔ Blob قبلی دست‌نخورده و فعلاً معلق است؛ لابی‌های آن یا نسخهٔ قدیمی گوشی‌میزبان منتقل‌شده اعلام نمی‌شوند. پس از انتشار نسخهٔ رایگان، همه صفحه را تازه کنند و لابی جدید بسازند. ادامهٔ اجرایی در [docs/LOCAL_CONTINUATION.md](docs/LOCAL_CONTINUATION.md) و [STATUS.md](STATUS.md) ثبت می‌شود؛ بخش‌های قدیمی [docs/SUPERPROMPT.md](docs/SUPERPROMPT.md) با درخواست تازه جایگزین شده‌اند.
